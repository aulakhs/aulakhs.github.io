Hermes Agent starter kit

Prompts for turning a fresh Hermes install into a personal operating assistant.

A practical sequence your agent can run: memory, private knowledge base, reusable skills, morning/evening briefings, content prep, job monitoring, maintenance jobs, and a self-improvement loop.

How to use this

Paste the prompts into your own Hermes agent in order. Replace bracketed placeholders before sending. Skip anything you do not need.

The shape is intentionally incremental: first establish identity and memory, then add skills, then schedule low-noise jobs.

Keep it privateDo not paste secrets, OAuth codes, API keys, cookies, or private client data.
Prefer low-noise jobsRoutine scripts should stay silent unless something actually needs attention.
Verify everythingEvery created skill, file, script, and cron job should be checked before moving on.
Prompt 1

Personal assistant baseline

I just installed Hermes. Help me turn it into my personal operating assistant.

First, inspect my Hermes setup and local environment safely:
- run `hermes doctor` if available
- inspect `~/.hermes/config.yaml` without exposing secrets
- inspect available toolsets and skills
- check whether memory, skills, cron, gateway, terminal, file tools, web tools, and messaging are available

Then create or update my personal assistant context so future sessions know how to help me.

My details:
- Name: [FULL NAME]
- What to call me: [PREFERRED NAME]
- Timezone: [TIMEZONE, e.g. America/New_York]
- Location: [CITY/REGION]
- Email: [EMAIL]
- Role/career context: [ROLE, TARGET ROLE, INDUSTRY]
- Current goals: [GOALS]
- Communication style: [e.g. concise, opinionated, no corporate filler]
- Things I want help with regularly: [briefings, job search, content, research, coding, admin]

Create a concise durable memory/profile from this. Do not store secrets. If a file-based knowledge base would help, propose a simple `~/knowledge/` structure and create it only after showing me the plan.
Prompt 2

Create a private knowledge base

Build me a lightweight private knowledge base modeled on a personal operating system.

Create a `~/knowledge/` directory with these sections:
- `identity/` for who I am, preferences, career goals, writing voice
- `memory/` for long-term memory, decisions, and interaction patterns
- `intel/` for current research/news/job/content intelligence
- `skills/` for recurring workflows written in plain English
- `tools/` for local tool inventory and commands
- `config/` for architecture, integrations, and scheduled jobs
- `projects/` for durable project notes

Populate starter files from what you know about me so far:
- `identity/about.md`
- `identity/preferences.md`
- `identity/career.md`
- `memory/long-term.md`
- `memory/decisions.md`
- `memory/interactions.md`
- `intel/latest.md`
- `tools/inventory.md`
- `config/architecture.md`
- `config/integrations.md`

Rules:
- Keep it private and local.
- Do not write secrets.
- Use placeholders where information is missing.
- At the end, summarize what you created and what questions I should answer next to improve it.
Prompt 3

Create a memory-system skill

Create a reusable Hermes skill called `memory-system` for maintaining my private file-based memory system.

The skill should cover:
- when to append daily notes vs update curated long-term memory
- directory layout under `~/knowledge/`
- privacy rules: never store secrets, credentials, OAuth codes, tokens, private client data, or raw sensitive messages
- daily note format
- how to synthesize repeated patterns into `~/knowledge/memory/long-term.md`
- how to update `identity/preferences.md` when I correct style or workflow preferences
- verification checklist

Use Hermes skill conventions: YAML frontmatter, Overview, When to Use, workflow steps, pitfalls, verification checklist.
Create it as a user-local skill under `~/.hermes/skills/note-taking/memory-system/SKILL.md` unless an existing equivalent skill already exists. If one exists, improve it instead of duplicating it.
Prompt 4

Daily briefing skill + scheduled morning briefing

Set up a daily morning briefing system for me.

First ask me for any missing details that materially change the setup, especially:
- preferred delivery channel: Telegram, email, Slack, CLI/local only
- preferred briefing time and timezone
- location for weather
- whether Gmail/Calendar access is configured or should be skipped
- topics I care about: [AI, career, company watchlist, markets, sports, etc.]

Then create a reusable skill called `briefing` that defines how to compile my daily briefing.

Default briefing sections:
- weather for my location
- calendar today/tomorrow, if available
- important unread email, if available
- system/Hermes health issues only if notable
- relevant news/intel, focused on my stated interests
- 1-3 recommended actions for the day

Quality rules:
- concise, useful, not noisy
- do not repeat yesterday's unchanged news
- cite links when using web sources
- if nothing meaningful changed, send a short no-change note or stay silent if this is a scheduled job and silence is supported

After creating the skill, create a Hermes cron job for the briefing using the cronjob tool or `hermes cron`.
Use a smaller/cheaper model for routine daily runs if my config supports it.
Set `enabled_toolsets` narrowly: usually terminal,file,web, plus messaging only if needed.
Verify the job appears in `hermes cron list`.
Prompt 5

Evening change-only briefing

Create an evening briefing cron job that sends only meaningful changes since the morning briefing.

Requirements:
- schedule: [TIME, e.g. 7pm local time]
- compare against the last delivered briefing or a compact state file under `~/.hermes/state/`
- include tomorrow's calendar if available
- include only new important email/news/health items
- avoid repeating unchanged stories
- final output should be empty if there is nothing useful and the delivery mechanism supports silent no-op

Persist a compact state file with delivered story signatures so future runs can dedupe.
Verify the job appears in `hermes cron list` and explain how to pause/resume it.
Prompt 6

Content writing skill

Create a writing skill for my LinkedIn/X/articles.

First interview me briefly for style calibration:
- paste 1-3 examples of writing I like
- paste 1-3 examples of writing I dislike, if available
- audience I write for
- topics I want to be known for
- phrases/tones to avoid

Then create a user-local Hermes skill called `[your-name]-writing`.
It should include:
- my target voice
- calibration examples
- opening patterns that sound like me
- what to avoid
- preferred post/article shape
- rewrite checklist
- verification checklist

Default style requirements unless I override them:
- polished and mature
- compressed, not over-explained
- opinionated but not performative
- no generic LinkedIn influencer tone
- no excessive lists or emoji
- write a perspective, not a source recap

After creating the skill, show me a one-paragraph sample in the new voice and ask if I want refinements.
Prompt 7

Weekly content prep scheduled jobs

Set up weekly content prep jobs for me.

Use my writing skill if it exists. If it does not, create it first.

Create two recurring scheduled jobs:
1. [DAY/TIME] — general thought-leadership draft
2. [DAY/TIME] — technical/builder/operator draft

Each job should:
- research current relevant news in my chosen topics
- select one strong angle, not a generic recap
- draft a LinkedIn post and a short X/Twitter version
- optionally include an image concept/prompt if relevant
- deliver to [Telegram/email/local]
- avoid posting publicly without explicit approval

Output format:
TOPIC
WHY NOW
LINKEDIN DRAFT
X DRAFT
OPTIONAL IMAGE CONCEPT
SOURCES

Use a cheaper model for routine content scouting if available, but use a stronger model when drafting final polished prose if needed.
Verify with `hermes cron list`.
Prompt 8

Job market monitoring skill + cron

Create a job-market monitoring system for me.

My target roles:
- Titles: [Director/VP/Head of X]
- Companies/industries: [TARGET COMPANIES]
- Location: [REMOTE/NYC/etc.]
- Compensation target: [COMP]
- Must-have filters: [e.g. leadership, AI-native, not IC, not contract]
- Nice-to-have filters: [e.g. platform, enterprise, GTM]

Create a skill called `job-market-monitoring` that defines:
- search queries
- source list
- fit scoring
- deduplication rules
- tracker file location, e.g. `~/.hermes/workspace/jobs-tracker.json`
- alert format
- update/persistence rules

Then create a scheduled job that runs [daily or twice daily] and only alerts on genuine new matches. If there are no new matches, update the tracker and stay silent.

Verify by doing a dry run with 3-5 searches and show me the tracker structure before scheduling if any write will happen.
Prompt 9

System health, backup, and spend monitoring

Set up low-noise maintenance jobs for my Hermes environment.

Create scripts under `~/.hermes/scripts/` and scheduled jobs for:
1. Hermes health check: run daily or hourly, alert only on real problems
2. API/model spend monitor: run daily, alert only if spending/usage crosses a threshold
3. Knowledge base backup: if `~/knowledge/` exists, back it up safely to [private Git repo/local archive/cloud drive], never exposing secrets
4. Weekly security audit: check suspicious configs/log errors/permission issues, summarize only findings

Rules:
- deterministic checks should be `script` + `no_agent=True` cron jobs to avoid wasting model tokens
- scripts must print nothing when there is nothing to report if silence is desired
- all error reports must redact secrets and tokens
- cron scripts must live under `~/.hermes/scripts/`; when scheduling with the cronjob tool, pass only the relative filename, not an absolute path

Verify scripts with shell syntax checks and show the final `hermes cron list` summary.
Prompt 10

Self-improvement system

Build a lightweight self-improvement system for my Hermes agent.

Create:
- `~/.hermes/self-improvement/learnings/LEARNINGS.md`
- `~/.hermes/self-improvement/learnings/ERRORS.md`
- `~/.hermes/self-improvement/learnings/FEATURE_REQUESTS.md`
- a simple script or process for scanning recent logs for recurring tool failures
- a skill called `self-improvement-systems` that explains how to maintain this system

Then create recurring review jobs:
- daily platform health review
- weekly security review
- weekly skill/learning review

Rules:
- do not create noisy reports
- report failures proactively through my configured messaging platform if available
- redact secrets
- if a recurring error has a known fix, add it to a skill or memory rather than just reporting it repeatedly

Verify the files exist and the jobs are scheduled.
Prompt 11

Personal article / URL knowledge base

Help me build a simple personal article knowledge base.

Goal:
When I send a URL or say "save this", Hermes should ingest the article, summarize it, store it locally, and make it searchable later.

Start simple:
- create `~/.hermes/workspace/personal-kb/`
- use SQLite or markdown files; choose the simplest reliable option
- store source URL, title, author if known, date, summary, tags/entities, and extracted text
- create scripts under `~/.hermes/scripts/`:
  - `kb-ingest.sh <url>`
  - `kb-search.sh <query>`
  - `kb-status.sh`

If Telegram/gateway is configured, propose a safe routing pattern where Hermes is the only Telegram front door. Do not let a sidecar bot poll the same Telegram token as Hermes.

After implementation, ingest one test public article, search it, and show verification output.
Prompt 12

Final audit and cleanup

Audit the personal Hermes operating system we just built.

Check:
- useful skills created and no duplicates
- memory/profile is concise and not overloaded
- `~/knowledge/` files exist if we created them
- cron jobs are low-noise and have sane schedules
- deterministic jobs use scripts/no_agent instead of spending model tokens
- agent jobs have restricted toolsets
- delivery channels work
- secrets are not stored in prompts, memory, knowledge files, or logs we created
- failure reporting is configured

Then give me:
1. a one-page summary of what exists
2. how to pause/resume each scheduled job
3. the top 5 improvements to make next
4. any broken auth/config items I need to fix manually
Optional

single bootstrap prompt if your friend wants one long request

I want you to configure my new Hermes install into a personal operating assistant. Do this incrementally and verify each step.

Build:
1. concise user memory/profile from the personal details I provide
2. a private `~/knowledge/` folder for identity, memory, intel, skills, tools, config, and projects
3. reusable skills for memory management, briefings, writing/content, job monitoring, and self-improvement
4. scheduled jobs for morning briefing, evening change-only briefing, weekly content prep, job monitoring, health/spend checks, backup, and weekly security/self-improvement reviews
5. optional simple article/URL knowledge base with ingest/search scripts

Operating principles:
- be low-noise; alert only when useful
- keep secrets out of memory, prompts, logs, and knowledge files
- use deterministic scripts with `no_agent=True` for simple checks
- use agent cron only for judgment-heavy work
- restrict toolsets for scheduled jobs
- verify every file/job you create
- never post publicly or send messages externally without explicit approval unless the scheduled job was explicitly created for that delivery

Before doing anything, ask me only the minimum missing questions: timezone, preferred delivery channel, briefing time, topics, career/content goals, and writing examples.
